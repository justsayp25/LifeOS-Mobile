# CLAUDE.md: LifeOS Mobile (Android APK)

Repo: https://github.com/justsayp25/LifeOS-Mobile (private). Versions: v1, then v1.1 ... v1.9, then v2. Each update bumps the number and `VERSION`.
Jess's dedicated Android app for LifeOS (Samsung S25+). Keep replies short and plain. Show Jess each result; work in small steps.

## What this app is (v1, standalone)
- The phone runs its own copy of LifeOS: **Termux** runs the LifeOS-Desktop server (`node server.mjs`, `127.0.0.1:4100`) against a phone copy of the vault. Claude Code on the phone (already installed by Jess) is the agent. No PC needed.
- This app is a thin Expo / React Native shell: a full-screen **WebView** on `http://127.0.0.1:4100/Phone.dc.html?view=phone` (the real dashboard pages; the look, glass and animations live in those pages, see `design/DESIGN.md`), plus a few native things:
  - **Start screen** when the server is down: "Start LifeOS" fires Termux's `RUN_COMMAND` intent (local Expo module `modules/termux-run`); fallback is a copy-able command and an "Open Termux" button.
  - **Menu** (the small ⋮ at the top right): Sync vault (`POST /api/gitsync/run`, vault sync through the private GitHub repo `justsayp25/LifeOS`, both copies kept on conflict), Update health data, Reload.
  - **Samsung Health**: `react-native-health-connect` reads steps, sleep and resting heart rate for the last 7 days from Health Connect (Samsung Health must sync to it) and posts daily totals to `POST /api/health/phone`.
  - Microphone and camera permissions for the pages (voice, photos); other links open in the browser.
- The dashboard, server, sync, agent and voice code all live in **LifeOS-Desktop** (`C:\Users\Jesse\Documents\Code\LifeOS-Desktop`, read its `CLAUDE.md`). Do not copy its logic here. Changes the app needs there go in `docs/DESKTOP-REQUESTS.md`.
- Phone setup (Termux, GitHub token, vault clone): `phone/SETUP.md` in LifeOS-Desktop.

## Contract with the server (LifeOS-Desktop >= v1.6)
- `GET /api/health` -> `{ok:true}` (the app polls this).
- `POST /api/gitsync/run` -> `{ok, pulled, pushed, saved, conflicts[], error?}`; `GET /api/gitsync/status`.
- `POST /api/health/phone` `{date:'YYYY-MM-DD', steps?, sleepMin?, restingHr?}`; partial days are merged, absurd values rejected.
- Start command on the phone: `bash ~/LifeOS-Desktop/phone/start-lifeos.sh`.

## Build (local, Windows PC)
See `BUILD.md`. Expo SDK 58, React Native 0.88, Gradle 9.4, needs JDK 17 (a portable one sits in the git-ignored `.tools/`), Android SDK in `%LOCALAPPDATA%\Android\Sdk`. `android/` is generated by `npx expo prebuild` and git-ignored. Do not use `expo-health-connect` (deprecated, breaks the build with duplicate classes; the plugin ships inside `react-native-health-connect`).

## Rules
- Never overwrite or delete the user's vault data. Test sync on a throwaway copy of the vault first, never the real one.
- Features are frozen: no new pages.
- No secrets, no Claude login, no keystore, no GitHub token in the repo.
- Report what was verified on a real phone and what was not.

## Direction from v1.3 (current; replaces the "native app" notes of v1.2)
Main screen = one WebView on `http://127.0.0.1:4100/?view=phone`. Opening the app shows "Starting R.E.N.E.E.", asks Termux (RUN_COMMAND) to run `~/lifeos-start.sh` (starts the LifeOS-Desktop server inside proot Ubuntu), polls `/api/health` for up to 30 s, then loads the WebView. On failure: message, Retry, Open Termux, Setup.
- The server never stops by itself (IDLE_MIN = 0); the idle stop exists in LifeOS-Desktop but is off.
- Menu also has "Auto-sync: on/off" (server saves 30 s after the last change and checks GitHub every minute; LifeOS-Desktop >= v1.8).
- Agent changes (LifeOS-Desktop >= v1.9): R.E.N.E.E. only proposes (add/complete task, tick habit, add capture, add event); a card with Yes/No (or a spoken yes/no) confirms; the Desktop server and pages do everything, so the app needs no change. Never delete, never Inbox/Journal. No native screen proposes or writes anything. Not run on the real phone yet.
- Samsung Health (v1.5.0): updates by itself when the app opens, when you return to it, and every 5 min while open (silent: never opens a permission page, uses what is already allowed). It now reads steps, sleep, resting heart rate, exercise minutes (ExerciseSession) and calories (Total, else Active) and posts them to `POST /api/health/phone` (LifeOS-Desktop >= v1.9.2 stores `active:` and `burned:` too). The menu item "Update health data" shows what it got and why anything is missing. Needs the new Health Connect permissions granted once (tap the menu item). Not verified on the real phone: sleep and resting heart rate were empty on the first run.
- Sync button (menu) = `POST /api/gitsync/run` on the server: phone vault copy <-> GitHub <-> PC. Never overwrites or deletes: conflicts keep both copies, a note deleted on the phone goes to `1 Human/99 Bin` (LifeOS-Desktop >= v1.7.1). The GitHub token lives only on the phone (git credential store inside Ubuntu), never in a repo.
- Kept but NOT the main screen: `src/vault/*` and `src/VaultApp.tsx` (in-app vault in a shared folder with isomorphic-git, tested by `node --experimental-strip-types tools/test-sync.mjs`; the manifest permission MANAGE_EXTERNAL_STORAGE was removed until it is used again) and the Kotlin Termux module (`modules/termux-run`).
- The APK is a release build signed with the debug key (standalone). A true Gradle debug build needs a Metro dev server and would not open on its own.
- Nothing from v1.1 on has been run on the real phone yet (as of v1.3.0).
